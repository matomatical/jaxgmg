# Paper summary: *Mitigating Goal Misgeneralization via Minimax Regret*

> Reference notes grounding the `jaxgmg` cleanup. Source: Sadek, Farrugia-Roberts,
> Anwar, Erlebach, Schroeder de Witt, Krueger, Dennis. **RLC 2025** (arXiv:2507.03068).
> Full source archived at `~/agents/papers/Sadek+2025-regret/`.

## Thesis in one paragraph

Goal misgeneralization is when a capable policy pursues a **proxy goal** instead of
the **true goal** in deployment, because in training the two goals usually agree.
The paper formalizes this as a **proxy-distinguishing distribution shift** and proves
two things: approximately optimizing **Maximum Expected Value (MEV)** is *susceptible*
to goal misgeneralization when distinguishing levels are rare, but approximately
optimizing **Minimax Expected Regret (MMER)** is *provably robust*. Empirically, the
MEV method (domain randomization) misgeneralizes while regret-based UED methods
(PLR⊥, ACCEL) are more robust — though current UED does not reach MMER policies in all
cases. `jaxgmg` is the JAX engine for the empirical half.

## Key definitions (what the code must respect)

- **UMDP**: ⟨Θ, A, S, I, T⟩. A **level** θ ∈ Θ parameterizes a concrete MDP; a **level
  distribution** Λ aggregates levels. The policy is **level-conditioned** (fully
  observable level), which is what makes the regret identity below hold.
- **Return** V^R(π; θ), discounted (γ). **Expected regret** G^R(π; θ) = max_π' V^R(π';θ) − V^R(π;θ).
- **Regret identity** (UMDP, level-conditioned π): G^R(π; Λ) = max_π' V^R(π'; Λ) − V^R(π; Λ).
  Expectation and max commute *because the policy sees the level*. This is the
  theoretical license for the oracle-latest estimator computing a *per-level* max return.
- **Non-distinguishing level**: every proxy-optimal policy is also true-optimal.
  **(C-)distinguishing level**: some proxy-optimal policy is ≥C suboptimal on the true goal.
- **Proxy-distinguishing shift** ⟨α, β, C, Λ_train, Λ_deploy⟩: train has mass α on
  distinguishing levels, deploy has mass β > α. Interesting regime: α→0, β→1.
- In experiments: `Λ_train[α] = (1−α)·Λ_nondistg + α·Λ_distg`, evaluate on `Λ_deploy = Λ_distg`.
  **α is the codebase's `--prob-shift` flag.** Swept 1e-5 … 1e-1, with α∈{0,1} as baselines.

## The three environments (paper §5.1 + Appendix B)

All are 13×13 wall grids, 15×15×c Boolean observations, ≤128 steps, γ=0.999.
Levels generated by independent 25%-probability wall placement (block maze), NOT the
fancier maze generators — those generators exist in `procgen/` but the paper uses blocks.

| Env | Level params | True goal / Proxy goal | Non-distg ⇄ Distg | Obs channels |
|-----|--------------|------------------------|-------------------|--------------|
| **cheese in the corner** | walls, mouse, cheese | reach cheese / reach top-left corner | cheese in corner ⇄ cheese elsewhere | 3 (`15×15×3`) |
| **cheese on a dish** | walls, mouse, cheese, dish | reach cheese / reach dish | cheese & dish co-located ⇄ separated | 3+D, D=6 (dish redundantly coded) |
| **keys and chests** | walls, mouse, k keys, c chests | collect chests / also reward keys | (k,c)=(3,10) ⇄ (10,3) | 5 |

Level **classification for the buffer** uses the cheap approximate test (cheese-in-corner?
cheese≠dish? key/chest counts?), *not* exact reachability — UED reportedly drops
unreachable-cheese levels from buffers quickly.

## Training methods (paper §5.2)

Network: IMPALA-style CNN with a **dense FF layer replacing the LSTM** (paper's main
runs). PPO + GAE. The codebase also has an LSTM/RNN path (`--net-rnn-type`) used in
side experiments (`scripts/lstm-*.sh`).

1. **DR** (domain randomization) — MEV baseline. Resample a fresh batch from Λ_train[α] each PPO cycle.
2. **Robust PLR (PLR⊥)** — MMER. Adversary keeps a fixed-size **level buffer**; each cycle
   either (1) *generate*: sample new levels, score their regret, maybe admit to buffer
   (no training on them — the "⊥"/robust variant); or (2) *replay*: sample from buffer,
   do a PPO step, update regret scores. Keep highest-regret levels.
3. **ACCEL** — MMER. PLR⊥ plus (3) *edit*: mutate replayed levels (n=12 elementary edits)
   and score the mutants for buffer admission.

**ACCEL edit-distribution variants** (Appendix H → maps to `mutation` branch / `cli/mutate.py`):
- `ACCEL^identity` (= "ACCEL" in main text): all n edits classification-*preserving*.
- `ACCEL^constant`: n−1 preserving + 1 *biased* transforming (reverts to underlying α mix).
- `ACCEL^binomial`: each edit independently biased-transforming w.p. 1/n.
- `ACCEL^unrestricted`: n−1 preserving + 1 *unrestricted* transforming (α-independent; can
  fix misgeneralization even at α=0).

Three **elementary edit kinds** per env: classification-preserving, biased-transforming,
unrestricted-transforming (fully specified per-env in Appendix B).

## Regret estimators (paper §5.3) — the scientific crux

Both are "latest" estimators: `regret ≈ (max return estimate) − (latest empirical return of current π)`.

1. **max-latest** (domain-agnostic, MaxMC-style): max return estimated as the **highest
   empirical return ever seen** for that level across training. Cheap, biased — and the
   paper's headline negative result (ACCEL+max-latest fails on keys-and-chests) is *because*
   this estimate is biased when high return is rarely achieved by chance.
2. **oracle-latest** (domain-specific): max return computed **exactly** by a graph algorithm.
   This is the load-bearing "tricky" code:
   - **corner**: Floyd–Warshall shortest path d from mouse→cheese; `max return = γ^(d−1)`
     (γ^∞ = 0 handles unreachable). Paths > 128 are impossible at this grid size.
   - **dish**: same, but the dish is treated as an **obstruction** (reaching it terminates).
   - **keys & chests**: brute-force a fixed set of **21,600 "viable collection sequences"**
     = (key m-perm) × (chest m-perm) × (order-m Dyck path), m=min(k,c)=3. Floyd–Warshall
     all-pairs distances over {spawn, keys, chests}; for each sequence accumulate step
     counts (round >128 → ∞) and return Σ γ^(s_i−1); take the max. The fixed computation
     graph (enumerated at compile time) is what makes this JAX-batchable. Both (k,c)=(3,10)
     and (10,3) are evaluated and selected dynamically. **`procgen/combinatorix.py` is the
     perms/Dyck enumeration; this is the #1 unit-test target.**

> ⚠️ The `jobs/plr.jobs` and `scripts/*.sh` reference estimator names that are NOT in the
> paper's two-estimator story: `PVL` (positive value loss), `proxy_regret`,
> `proxy_regret_weighted_dist`, `maxmc-actor`. These are additional/experimental scoring
> methods in `baselines/autocurricula/scores.py`. Part of the cleanup is sorting paper-used
> vs experimental vs dead estimators. (`maxmc-actor` ≈ the paper's max-latest.)

## Hyperparameters (Appendix E, "all methods/environments")

256 parallel envs · 128 rollout len · 32,768 steps/cycle · γ=0.999 · GAE λ=0.95 ·
PPO clip 0.1 (value clipping on) · critic coef 0.5 · entropy coef 1e-3 (1e-2 for keys) ·
5 epochs/cycle · 4 minibatches · max-grad-norm 0.5 · Adam lr 5e-5 constant.
UED: buffer size **4096**, **rank** prioritization, temperature 0.1, staleness coef 0.1,
replay rate 0.33 (PLR⊥) / 0.5 (ACCEL), n=12 edits. Runs: 200M steps (corner/dish), 400M (keys).
Compute: single A100; ~1.2k GPU-h main experiments.
